Ollie, a secretary that lives in WhatsApp

You text it or send a voice note. It keeps your reminders, notes and calendar, watches for messages you shouldn't miss, and drafts replies you approve with a typed "yes". It runs on your own server and answers only you.

How a message travels

  1. Your WhatsApp
  2. OpenWA gateway
  3. The bot
  4. AI model + tools
  5. Reply

OpenWA is a separate self-hosted program that connects to WhatsApp. It forwards each message to the bot over a signed webhook. The bot ignores every number except yours, asks an AI model what to do, runs the tools it picks (a reminder, a note, a calendar entry) and answers through OpenWA. Voice notes are turned into text first.

Things to try first

Talk to it

  • "Remind me to call the bank tomorrow at 10"
  • "Save a note: ideas for the club poster"
  • "What's on my calendar this week?"
  • Send a voice note instead of typing
  • "Message Sam: running 10 minutes late". It shows you the draft and sends only after you reply yes.

Ask it to look after things

  • /briefing a morning summary: calendar, weather, tasks, birthdays
  • /wrap an evening wrap-up with tomorrow's plan
  • /pending who is still waiting for your reply
  • /alerts what it flagged as urgent

What you need

Required

  • A small always-on Linux server with Docker
  • A WhatsApp number for the bot (a spare SIM works)
  • An AI key: OpenRouter, or Gemini
  • A Groq key if you want voice notes understood

Optional

  • Google account access for Calendar and Gmail
  • A second, read-only link to your own WhatsApp for the inbox, unread and alert features
  • A private GitHub repo to back up your notes
Costs. The software is free. You pay for the server (a free-tier VM works) and for AI usage by the token. Use low-cost models, set DAILY_SPEND_LIMIT_USD, and check /usage now and then.

Set it up

Tick each step as you finish it. Your progress stays in this browser.

0 of 7 done
1. Get a server and Docker

Any Linux server with Docker and Docker Compose will do. ARM works. Keep ports closed to the internet except what you already use for SSH.

2. Run OpenWA and link the bot's WhatsApp

Install OpenWA from its repository and start it with Docker. Create one session for the bot, open its QR code, and scan it from the bot's phone under Linked devices. Note the session id and create an API key for it.

In OpenWA's own .env add these two lines so it can reach the bot and read contact numbers:

SSRF_ALLOWED_HOSTS=wa-bot
RESOLVE_LID_TO_PHONE=true
3. Get the bot and fill in its settings

Put the bot's folder next to OpenWA (for example ~/OpenWA/wa-bot), then copy the example settings file and edit it:

cd ~/OpenWA/wa-bot
cp .env.example .env
nano .env

The settings that matter most:

SettingWhat to put
OPENWA_URLRequiredhttp://openwa-api:2785
OPENWA_API_KEYRequiredThe API key you made for the bot's session
WEBHOOK_SECRETRequiredA long random string (16+ characters). You reuse it in step 5.
OWNER_NUMBERSRequiredYour own number, digits only with country code. The bot answers only this.
AI_PROVIDERRequiredopenrouter (or gemini) with its key: OPENROUTER_API_KEY / GEMINI_API_KEY
GROQ_API_KEYOptionalLets it understand voice notes
TZOptionalYour timezone, for example Asia/Colombo
DAILY_SPEND_LIMIT_USDOptionalA daily cap so a bug can't run up a bill
BRIEFING_TIME, WRAP_TIMEOptionalWhen the morning and evening summaries arrive
Never share or commit .env. It holds your keys. It is already ignored by git.
4. Add the bot to Docker Compose

In the OpenWA folder, create docker-compose.override.yml so one command starts both:

services:
  wa-bot:
    build: ./wa-bot
    container_name: wa-bot
    restart: unless-stopped
    env_file: ./wa-bot/.env
    volumes:
      - wa-bot-data:/data
    networks:
      - openwa-network
    depends_on:
      - openwa-api

volumes:
  wa-bot-data:

The wa-bot-data volume holds the database and your notes, so they survive rebuilds.

5. Tell OpenWA where to send messages

Register a webhook on the bot's session. Use the same secret as WEBHOOK_SECRET. Messages without a valid signature are rejected.

curl -X POST http://127.0.0.1:2785/api/sessions/<bot session id>/webhooks \
  -H "X-API-Key: <bot api key>" -H "Content-Type: application/json" \
  -d '{"url":"http://wa-bot:3000/webhook","events":["message.received"],"secret":"<WEBHOOK_SECRET>"}'
6. Build and start
cd ~/OpenWA
docker compose up -d --build wa-bot
docker logs -f wa-bot

You should see a line saying the bot is listening on port 3000.

When you rebuild later, always add --no-deps (docker compose up -d --build --no-deps wa-bot). Without it, OpenWA restarts too and every linked WhatsApp session disconnects.
7. Say hello

From your own number, message the bot "hello", then send /help. If it answers, you are done. Next, turn on the extras you want from the table below.

What it will and won't do

It will not

  • Answer anyone but the numbers in OWNER_NUMBERS
  • Send a message or email without you typing yes to the exact text
  • Reply from your personal WhatsApp. That link is read-only and every write is refused in code.
  • Chat with strangers on its own. AI chat with an outside person starts only after you run /allow.
  • Mark your chats as read

It does

  • Hide names, numbers and emails from the AI behind placeholders, and put them back in its answer (/pseudo)
  • Use AI providers on zero-data-retention routing for private text
  • Keep chat-derived notes in a private folder the AI cannot read
  • Cap daily spend and email and message counts

Why messages from other people are treated carefully

Anything another person writes, in a chat or an email, could contain instructions meant to trick an AI. So that text only ever goes to a model that has no tools, which can summarize but can't send, delete or search. Email recipients are checked in code: after the bot reads an email, it will only offer to send to the person who wrote it or to someone in your contacts, and anything else needs you to type yes followed by the address.

Keep it that way. If you extend the bot, never pass text from outside people to a model that can use tools.

Good habits

  • Keep .env private and rotate a key if it ever leaks.
  • Check /usage weekly while you are getting started.
  • Start with the read-only features. Turn on sending last.

When it breaks

The bot doesn't answer at all

Run docker logs --tail 50 wa-bot. Check that your number is in OWNER_NUMBERS (digits only), that the webhook secret matches on both sides, and that the bot's session is ready in OpenWA.

Everything stopped after I restarted OpenWA

A restart disconnects every linked session. Start the bot's session again in OpenWA, and the personal one too if you use it. Rebuilding the bot with --no-deps avoids this.

It says it can't reach the AI, or credit ran out

Check the key in .env and your balance with the provider. /usage shows what it spent today. If you hit the daily cap, raise DAILY_SPEND_LIMIT_USD.

Voice notes aren't understood

Add GROQ_API_KEY to .env and rebuild.

The notes can't be updated (permission denied)

Files in the wa-bot-data volume must belong to the bot's user. If you copied notes in by hand, fix the owner with docker exec -u root wa-bot chown -R 1000:1000 /data/vault.

Alerts or unread show nothing

These need the personal session and its webhook to include message.received, message.sent and call.missed. Check /watch for what is being watched and your quiet hours.

Run the tests before changing code

There is no Node on the host, so use Docker: docker run --rm -v "$PWD":/app -w /app node:22-alpine node --disable-warning=ExperimentalWarning scripts/test-mock.js

Built with Node 22 built-ins only, no packages to install. Notes are plain Markdown files you can also open in Obsidian.
